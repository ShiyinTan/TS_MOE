# Results layout

Final evaluation **metrics and reports** are stored under a top-level `results/` directory. Checkpoints, caches, and training history stay under `runs/`.

## What goes where

| Location | Contents |
| --- | --- |
| `runs/<city>/cache/` | `prepare` cache (`manifest.json`, split `.pt` files, SURD tables) |
| `runs/<city>/model/` | `train` checkpoint `best.pt` and per-epoch `history.json` (full val metrics; optional per-epoch `test`) |
| `results/<run_name>/eval_validation/` | Best-checkpoint **validation** metrics after `train` |
| `results/<run_name>/eval_test/` | Final **test** metrics after `train` (`metrics.json` + `report.txt`), or default output of `evaluate --split test` |
| `results/<run_name>/eval_test/epoch_NNN.json` | Per-epoch **test** on current weights when `--eval-test-every-epoch` (default **on**) |
| `results/<run_name>/history.json` | Compact per-epoch val (+ test) Acc@1 / NDCG@1 / MRR under `results/` |
| `results/<run_name>/candidate_pool_stats.json` | Per-split candidate-pool size stats printed at train start (min/max/mean/median) |
| `results/ablation_log.md` / `.csv` | Auto-appended ablation rows after each `train` / `evaluate` (see [`ablation.md`](ablation.md)) |
| `results/ablation_summary.md` / `.csv` | Master table regenerated by `python -m tsmoe ablation-summary` (all_targets + known_only + run-name ↔ flags check) |

Each `eval_*` directory contains:

- `metrics.json` — full payload (Acc/Hit/Recall, NDCG, MRR, MAP @1/5/10/20, `all_targets` / `known_only`, groups, device, cache id, timestamp, model config, `candidate_construction`, optional `candidate_pool_stats`, …)
- `report.txt` — same summary printed to the terminal (Acc@1 headline + tables)

Ranking is over the cache candidate set (spatial neighborhood by default; see [`candidates.md`](candidates.md)), not necessarily the full POI catalog.

**`known_only`:** metrics on samples whose ground-truth next POI is **in the training catalog** (out-of-catalog targets are dropped from the denominator). This is **not** “only when the target is in the candidate pool” (GT is always forced into the pool). Chinese one-liner and details: [`ablation.md`](ablation.md) §6.1. To **remove** unknown users / out-of-catalog targets from the prepared val/test data (STHGCN-style), use `prepare --filter-unknown on` (default **off**; re-prepare) — that is a different ablation from `known_only`.

Optional: `evaluate --output path.json` still mirrors the JSON to an extra path.

### Master summary table

```bash
python -m tsmoe ablation-summary --results results
# → results/ablation_summary.md + .csv
```

Scans `**/eval_test/metrics.json`, merges `ablation_log.*` when present, and flags leaf run names that disagree with recorded settings (see [`ablation.md`](ablation.md) §6.2).

## How `<run_name>` is chosen

Defaults derive from the train `--out` / checkpoint directory by stripping a leading `runs/` segment under the working directory:

| Train / checkpoint path | Default results root |
| --- | --- |
| `runs/tokyo/model` (or `…/best.pt`) | `results/tokyo/model/` |
| `runs/demo/model` | `results/demo/model/` |

So:

```text
results/tokyo/model/eval_validation/{metrics.json,report.txt}
results/tokyo/model/eval_test/{metrics.json,report.txt}
results/tokyo/model/eval_test/epoch_001.json   # when --eval-test-every-epoch (default)
results/tokyo/model/history.json
results/ablation_log.md
results/ablation_log.csv
```

Override the eval destination with `evaluate --out <dir>` (writes `metrics.json` + `report.txt` directly in that directory).

## Per-epoch test (default on)

After **each** training epoch, `train` also ranks the **test** split on the **current** weights (validation selects `best.pt` by `--checkpoint-metric`, default **NDCG@10**; use `acc1` to select by Acc@1). Disable for speed:

```bash
python -m tsmoe train --cache runs/tokyo/cache --out runs/tokyo/model --no-eval-test-every-epoch
```

Per-epoch files: `results/<run>/eval_test/epoch_001.json`, … plus compact `results/<run>/history.json`. Final best-checkpoint test still overwrites `eval_test/metrics.json`.

## Finding Acc@1 after train

```bash
# From repo root, after:
#   python -m tsmoe train --cache runs/tokyo/cache --out runs/tokyo/model
python -c "import json; m=json.load(open('results/tokyo/model/eval_test/metrics.json')); print(m['all_targets']['Acc@1'])"
# or read the human report:
grep -E 'summary|Acc@1' results/tokyo/model/eval_test/report.txt
```

Primary headline metrics in reports are **Acc@1**, **NDCG@1**, and full **MRR** (`all_targets`). Checkpoint selection during training defaults to validation **NDCG@10** (`--checkpoint-metric ndcg10`); Acc@1 hillclimbs may pass `--checkpoint-metric acc1`.

For STHGCN-style comparisons, also read **`known_only` Acc@1** (in-catalog GT targets only) from `eval_test/metrics.json`:

```bash
python -c "import json; m=json.load(open('results/tokyo/model/eval_test/metrics.json')); print(m['known_only']['Acc@1'])"
```

Optional Acc@1 ranking auxiliaries (see also [`causal-counts.md`](causal-counts.md)):

| Flag | Role |
| --- | --- |
| `--lambda-bpr` | Hard-neg BPR weight `softplus(-(s_pos-max_neg-margin))` (default 0) |
| `--bpr-margin` | Logit margin inside BPR (default 0; only if λ_bpr > 0) |
| `--transition-score-bias` | `λ·log1p(last→cand POI transition)` added to scores (default 0) |
| `--surd-bias-gate` / `--surd-score-bias` / `--tsb-gate-mode` / `--surd-attn-gate` | SURD/SMI-controlled bias weights (all default off / 0; see [`causal-counts.md`](causal-counts.md)) |

**LOCKED WIN (Tokyo known_only vs STHGCN):** `hc_sg_Atime_bpr029_ssb026` — Acc@1 **0.260274**, R@5 **0.441517**, R@10 **0.519494**, R@20 **0.586934**. Full flags in [`ablation.md`](ablation.md) §3.2 / [`causal-counts.md`](causal-counts.md).

## Relation to `runs/`

- **Do not** look under `runs/.../model/eval_*` for metrics — those paths are no longer used.
- `runs/` remains the place for heavy artifacts you may want to keep or delete independently of published numbers.
- Both `runs/` and `results/` are gitignored; only code and docs are tracked.

## Example commands

```bash
python -m tsmoe prepare --data-root data --city tokyo --out runs/tokyo/cache
python -m tsmoe train --cache runs/tokyo/cache --out runs/tokyo/model
# → checkpoints: runs/tokyo/model/best.pt
# → results:     results/tokyo/model/eval_validation/ and .../eval_test/
# → per-epoch:   results/tokyo/model/eval_test/epoch_*.json + history.json (default)
# → ablation:    results/ablation_log.md and .csv (auto-append)

python -m tsmoe evaluate --cache runs/tokyo/cache --checkpoint runs/tokyo/model/best.pt --split test
# → results/tokyo/model/eval_test/{metrics.json,report.txt}
# → also appends a row to results/ablation_log.*
```
